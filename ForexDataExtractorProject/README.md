# Forex Data Extractor & Real-Time Trading Project

This project is a complete quantitative forex trading system designed to connect with the **Interactive Brokers (IBKR) API** (via `ibapi`). It handles historical data downloads, advanced feature engineering (technical indicators and dynamic support/resistance zones), model training (Jupyter-based machine learning pipelines), and real-time execution (tick aggregation, ML predictions, and live trading with bracket orders).

## ⚙️ Core Modules & Mechanics

### 1. Data Ingestion (`src/data_extraction/`)
* **[download_data.py](src/data_extraction/download_data.py)**: Downloads historical forex midpoints in 1-month chunks from IBKR. It parses dates to New York timezone, segments data by month, and saves it to `data/<ticket>/<candlesize>/<YYYYMM>.csv`.
* **[extractor.py](src/data_extraction/extractor.py)**: Standard historical data extraction script mapping incoming bars to localized data tables.

### 2. Feature Engineering & Preprocessing (`src/utils/`)
* **[exploration_utils.py](src/utils/exploration_utils.py)**: Preprocesses data into UTC. Calculates features including:
  * *Candlestick Metrics*: Range, body size, shadow ratios.
  * *Moving Averages (SMAs)*: Crosses, orders, slopes, momentum, and acceleration in pips.
  * *RSI/Bollinger Bands/Stochastics*: Distance to zones, crossovers, squeezes, divergences, and momentum.
  * *Target Variable Generation*: Simulates trading scenarios to verify if the future window hits a profit target first (`objetivo_compra_alcanzado` / `objetivo_venta_alcanzado`), hits stop loss, or stays neutral within a set horizon.
* **[support_resistance.py](src/utils/support_resistance.py)**: Detects local extrema using `scipy.signal.find_peaks` on high/low/close prices. Groups these points into dynamic clusters (`cluster_all_points_dynamic`), calculating importance scores, reaction magnitudes, durations, and role changes. Columns indicating proximity to active support/resistance lines are joined back to the trading data.

### 3. Live Processing & Trading Engine (`src/app/`)
* **[realtime_processor.py](src/app/realtime_processor.py)**: The core live production application:
  1. Establishes a socket connection to IBKR Gateway/TWS.
  2. Solicits 5-second real-time bars.
  3. Groups and aggregates ticks into 5-minute OHLCV bars.
  4. Combines real-time data with historical data downloaded on cold startup (usually 2 days of backfilled data) to calculate lagging features.
  5. Feeds the Random Forest models.
  6. Evaluates output probabilities against calibrated optimal thresholds (`optimal_buy_threshold`, `optimal_sell_threshold`) rather than standard 0.5 rules.
  7. If a threshold is crossed, it places a **Bracket Order** (parent Market order coupled with child Limit Take Profit and Stop Loss orders).

## 📊 Models & Metadata Configuration
* The serialized models are saved in the `models/` directory.
* The `metadata.json` file companion specifies:
  * **optimal_buy_threshold**: Probability threshold above which a buy bracket order is triggered.
  * **optimal_sell_threshold**: Probability threshold above which a sell bracket order is triggered.
* These parameters are tuned inside the Jupyter notebooks (`notebooks/`) by analyzing cumulative pip returns against specific transaction costs.

## 🛠️ Requirements & Development Environment
The environment is managed via **Poetry** using **Python 3.11**. Key dependencies include:
* `ibapi` - Interactive Brokers API Client/Wrapper
* `pandas` & `numpy` - Data processing and vector operations
* `scipy` - Signal processing for peak/valley detection
* `scikit-learn` & `lightgbm` - Classification pipeline models
* `joblib` - Model persistence and loading
* `plotly` & `matplotlib` & `seaborn` - Plotting and visualization
